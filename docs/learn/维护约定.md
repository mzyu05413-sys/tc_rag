# 学习文档维护约定

1. `docs/design/` 维护当前架构和开发计划；`docs/learn/` 解释已实现代码；`docs/reference/` 查询契约、计时和提示词版本。
2. 当前只有 RAG 主线。阶段表示开发顺序，配置开关表示同一流程的扩展，不能再写成并行生成路线。
3. 每阶段一个 README 提供阅读顺序；总览维护完整流程和命令，步骤章讲具体算法、代码、例子、验证和局限。
4. 章节回答“为什么做 → 输入输出 → 流程与代码 → 例子 → 验证 → 局限”，不以零散修改记录代替教程。
5. 直接更新失效内容，不用顶部警告保留与当前实现冲突的正文。删除重复/无关文档，未来阶段只在开发指南规划，代码落地后再建学习页。
6. 分开说明代码已实现、离线验证、真实模型效果和人工业务批准。测试数仅放在有日期的验证记录，不能作为永久状态。
7. 移动或删除文档时同步更新所有导航、相对链接、README 和 AGENTS；检查 UTF-8、文件链接、锚点和代码示例。
8. 私有需求、金标与运行产物留在 `workdir/`；学习示例使用虚构数据。中文解释，英文标识符保留原名。
9. 提示词业务变更另建版本，记录版本和指纹。文档中的规划和命令示例不自动授权执行、付费调用或 Git 提交。
