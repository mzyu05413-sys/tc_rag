# P1.10 测试点目录与联合导出

[返回学习导航](../README.md) · [P1 总览与完整命令](01_功能架构与流程.md)

## 先理解目的

一次生成测试点和用例后，同时提供便于浏览的目录与可执行的详细用例。

## 输入和输出

SQLite 测试点与校验后的用例 → 同目录的测试点 XMind、用例 Excel 和质量报告，文件名带需求名称后缀，以 CLI 输出路径为准。

## 处理流程与代码阅读

`Pipeline.generate()` 连续完成规划和用例生成；`cases()` 保留全部测试点目录，
按“状态 → 业务维度 → 功能 → 测试目标”组织。XMindAdapter 导出分组、测试点标题及 point_id 元数据，
不包含用例标题、步骤、前置条件和预期。Excel 显示详细用例，并附测试点、规则、覆盖和问题表。
两份文件在首次运行目录一起交付；之后重新生成使用独立 `batch_*` 子目录。
manifest 记录配置、提示词与 Skill 指纹、调用及耗时，SQLite 始终是事实来源。

先读 `src/tc_rag/interfaces/workflow.py` 的入口及中文注释，再沿其调用进入端口和领域模型。文件路径从项目根目录起算。

## 用一个例子理解

上限 300 的独立测试点为 299、300、301。三个有效用例输出到 Excel，脑图只列三个检查目标。
如果某个用例未生成，脑图仍保留该测试目标及状态，Excel 的测试点表与问题清单记录缺漏。没有就绪点时用例表可以只有表头。
用户修改 XMind 只改变目录视图，不改变 SQLite 事实；重试生成不需要回传脑图。

## 验证和审核

自动验证见 `tests/integration/test_pipeline.py`：目录包含全部测试点及对应状态，Excel 用例只引用合法测试点、
不导出步骤到脑图、空结果显式报告、重试不读取被修改的 XMind。

## 当前边界

XMind 为单工作表普通子节点，实际客户端打开兼容性仍需验收。自动校验只记录技术风险，
不会创建人工批准记录，也不暂停生成等待审核。
