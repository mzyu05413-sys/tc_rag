# P1 基础模块、代码架构与流程

[返回学习导航](../README.md) · [当前完整 RAG 流程](../P2/README.md)

P1 是 RAG 主线使用的基础模块，不再提供独立生成路线。阅读本章理解原文如何变成
有依据的测试点和用例；运行配置及完整命令统一看 P2 总览。

## 对象之间如何衔接

Document 保存文件内容版本；DocumentBlock 保存段落、表格或图片及定位；Chunk 保留
Block 的字符区间。模型从这些输入提炼 EvidenceSpan、Feature 和 RequirementRule，
程序核验引文、来源与引用闭包，再归并规则。

RAG 对原文片段和有效证据做 embedding、建索引与检索，补充条件和例外。
规划出的 TestPoint 保存到 SQLite 后，根据同一版本的规则和证据再次检索，结合用例 Skill
生成 TestCase，最后联合导出测试点目录 XMind、详细 Excel、覆盖矩阵和问题清单。

最大值 300、整数精度 0 的边界由程序推导成 299/300/301；无法确定的精度、权限、
状态或文案进入待确认，不能依靠模型自行补全。

## 代码从哪里看

| 层或模块 | 主要代码及职责 |
|---|---|
| 入口 | `src/tc_rag/interfaces/workflow.py`：输入、配置、Skill、诊断和结果路径 |
| 编排 | `src/tc_rag/application/orchestration/pipeline.py`：连续流程、并发、预算、RAG、持久化 |
| 端口 | `src/tc_rag/application/ports/contracts.py`：模型、向量、解析、检索、导出替换边界 |
| 领域 | `src/tc_rag/domain/`：文档、证据、规则、测试点树与用例契约 |
| 基础服务 | `src/tc_rag/application/services/`：分块、引文、规划、覆盖和评估 |
| 外部实现 | `src/tc_rag/infrastructure/`：DOCX/PDF、模型 SDK、SQLite、索引与导出 |
| 装配 | `src/tc_rag/bootstrap.py`：强制装配生成与 embedding，注入必需检索器 |

依赖方向是 interfaces → application → domain；infrastructure 实现端口。
SQLite 是业务事实来源；JSON、Markdown、XMind、Excel 和索引都能作为派生产物重建。

## 为什么保留中间测试点

测试点将“测什么”与“怎么测”连接起来，记录规则引用，供后续 RAG 查询和覆盖检查。
它是内部业务事实，不再是中间审核门槛；`generate()` 直接串联 `points()` 与 `cases()`。
XMind 只展示已有用例对应的测试点。Skill 只影响生成表达，不能创造需求事实。
Schema 和引用通过只说明技术约束满足，输出的业务含义仍须在使用中核实。

## 基础模块测试

`tests/integration/test_pipeline.py` 使用虚构 DOCX 和显式模型、向量替身，实际执行
RAG 索引/检索、测试点目录、用例及 Excel；不会调用真实模型。
`test_rag.py` 验证规划和生成均检索；`test_case_skill.py` 验证 Skill；交互测试验证一次执行。
