# P1.4 清洗、分块与引文校验

[返回学习导航](../README.md) · [P1 总览与完整命令](01_功能架构与流程.md)

## 先理解目的

原始 Block 太大，不适合直接送入模型。Chunk 是处理单元，原始文字仍以 Block 为准。

## 输入和输出

DocumentBlock 列表 → Chunk 列表与预算问题。sources 记录原始块内左闭右开字符区间。

## 处理流程与代码阅读

按章节和段落组织，完整段落重叠；条件后的例外尽量一起保留。大表按完整行拆分并重复首行。PDF 同一张表跨页时，解析库会产出多个 table Block；续页片段会重复起始表头行，表头只重复来源区间，不改写原文。原文不改写；全半角与空白归一化只用于核验引文。

先读 `src/tc_rag/application/services/chunking.py` 的入口及中文注释，再沿其调用进入端口和领域模型。文件路径从项目根目录起算。

## 用一个例子理解

最多300个 + 但管理员除外，必须同时进入上下文；不能只截取第一句。

## 验证和审核

自动验证见 `tests/unit/test_design.py`。审核时沿“原文 → 规则 → 测试点 → 步骤预期”反向查一次，确认每个结论都能找到输入依据。

## 当前边界

大段落或单表行超预算会报告或失败；不承诺任意 PDF 页眉页脚自动清洗。续页表头按相邻页、同章节、同列数识别，可能误判相邻的两张同列数表；补入表头后超出预算仍报告，不截断原文。

## 可选策略与验收

默认保持原分块结果；新增配置默认值不进入快照。三个策略可独立启用：

- `attach_headings=true`：纯标题待输出时随下一单元进入分块；末尾标题仍保存。标题加大表按完整行继续拆，标题仅作为第一组前缀，每组重复首行。
- `min_tokens=200`：当前小节不足阈值且与下一单元同父或下一级、同一级根章节、合并不超目标预算时合并。0 关闭，必须小于 target_tokens；跨小节不产生重叠。
- `split_long_paragraphs=true`：只对超预算 paragraph（含视觉派生文字）按换行/句末标点分组，相邻条件与例外尽量连在一起，保留原文字符区间。无句界的长句不硬切，整块加 warning；拆段本身也记录 gap warning。

图片及解析器标记的 `other` 不进入分块；表格按 JSON 行的真实原文区间引用，不重新序列化行来冒充原文。完整 Block 留在数据库；Chunk 不是对原文的替换。每个符合条件的非空 Block 至少有一个来源引用，段落区间覆盖全部文字，Chunk 文本逐字等于各来源切片加换行。

更换策略会改变 Chunk 指纹，使受影响的提炼缓存失效。历史快照、已有 RAG 记录和视觉缓存不会因此被删改；新运行的提炼和检索/生成仍可能重新计费。

```powershell
rag chunk-stats <run_id>
rag chunk-stats <run_id> --compare
rag chunk-stats <run_id> --compare --min-tokens 200 --split-long-paragraphs
```

这些命令不调用模型、不改主库；查看产物的 `review.md`、`comparison.json` 和 `statistics.json`。
回归见 `tests/unit/test_chunk_structure.py`、`tests/integration/test_chunk_stats_cli.py`；详细策略、实测和审核清单见[分块质量指南](../../reference/chunk_structure_quality.md)。
