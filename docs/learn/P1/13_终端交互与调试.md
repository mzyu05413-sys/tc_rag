## 配置位置

CLI 按显式 `--config`、`workdir/local.yaml`、`config/defaults.yaml` 选择配置文件。
之后叠加环境变量与命令覆盖。当前只运行 RAG，生成模型和向量模型都必须配置。
旧 `retrieval.mode` 字段、CLI `--mode` 和 `planning.llm_supplement` 已移除；删除旧配置项，并清除旧环境变量 `TC_RAG_RETRIEVAL__MODE`。规划始终经过 RAG 增强，不能跳过检索。
旧运行可继续查询；若配置快照不符合当前契约，应重新生成。旧批准记录不参与当前流程。

密钥可直接填在 `workdir/local.yaml` 的 `models.<role>.api_key`，不需要每次设置终端变量。
非空配置密钥优先，留空时才回退 `api_key_env`；后者仍要求运行进程能读到环境变量。
密钥字段不进入配置快照、数据库、诊断配置和导出，公共模板仅保留空值。生成、embedding、vision 和 rerank 使用相同规则。

## 两项检查

```powershell
# 离线：检查所有必需端点与配置/环境变量中的密钥，不访问模型。
.\.venv\Scripts\python.exe -m tc_rag.interfaces.cli doctor
# 显式真实检查：虚构需求经提炼、向量化、检索增强到 XMind。
.\.venv\Scripts\python.exe -m tc_rag.interfaces.cli doctor --live
```

离线通过不证明密钥有效或模型可访问。真实检查最多发送 8 次生成和 embedding 请求，
不重试、不修复输出，仅诊断到测试点。材料使用独立数据库，保存在
`workdir/diagnostics/诊断ID/`，不影响业务运行。
检查需得到有效索引和检索记录，并形成 299/300/301 边界测试点；业务语义仍需人工核验。
图片、rerank 和完整用例生成不包含在这个小型诊断中，应按主线说明另行验收。

## 启动与进度

```powershell
.\.venv\Scripts\python.exe -m tc_rag.interfaces.cli start
```

输入需求路径，路径支持空格及成对引号；交互入口使用内置目标，自定义目标用 `rag run 文件 -i '生成目标'`。
启动在输入前检查必需模型和密钥，随后连续规划和生成，在同一运行目录输出带需求文件名的 XMind 与 Excel。
脑图包含全部测试点及待澄清点，Excel 展示实际生成用例；无需 `review` 或批准记录。
默认使用内置用例 Skill；`--skill-file "规范.md"` 或 `generation.skill_file` 可追加规范。
`--preview` 仅显示计划，不调用模型；`--quiet` 隐藏进度，保留结果和错误。
输入期间 Ctrl+C 不开始生成；运行期间 Ctrl+C 会取消并等待并发任务收尾，退出码为 130。

终端先展示流程路径，再按实际执行顺序给阶段编号，显示处理说明、批次进度和耗时，
普通进度与等待心跳共享约 20 秒间隔。规划与生成阶段同时累计 RAG 检索、重排成功及降级数量；
重试和结构修复即时提示，模型缓存命中集中汇总，减少刷屏。
结束时列出阶段耗时；失败或取消时将当前阶段标记为中断。完成顺序可与开始顺序不同，
最终仍按原文顺序归并。详见[完整运行过程](../../reference/full_run_walkthrough.md)。
进度写到 stderr，结果写到 stdout；不输出原始思考、需求正文或凭据。

## 速度与错误

文件大小不能直接代表模型耗时。来源定位、输出 Schema、重试和服务商响应速度都会影响耗时。
提炼、测试点规划、用例生成按 `models.llm.concurrency` 有界并发；完成后按输入顺序归并。
embedding 按其 batch_size、concurrency 执行；视觉有独立的并发上限、启动间隔、限流冷却与缓存。
RAG 的索引和查询也会产生向量请求；不能只用分块数量估算全部调用。
当前配置下的真实耗时仍需实测。

DeepSeek Chat 使用 `response_format: json_object`；程序仍执行本地结构与原文引用校验。
`thinking_mode: default` 不发送扩展参数，其他取值仅用于服务商明确支持的 Chat 接口。
`runtime.max_context_tokens` 包含完整输入，不会扩大远端模型上下文窗口，须预留输出空间。

`models.llm.max_output_tokens` 控制单次输出长度，不能通过增加输入预算来替代。
留空沿用服务商默认；Chat 协议发送 `max_tokens`，Responses 协议发送 `max_output_tokens`。
例如 DeepSeek 非思考模式默认输出上限为 8192，复杂提炼 JSON 可先配置为 16384，
并核对服务商模型允许的范围、输入与输出总窗口。截断结果不会被当作有效结果保存。
修改此配置后应重新开始运行，避免混用配置与旧阶段事实。

图片解释有独立进度与成功/失败汇总。视觉端点对 429、可重试 HTTP 错误及连接超时
按 `runtime.max_attempts` 有界重试。连续 429 会跨图片冷却 10、20、40、60 秒，
秒数形式的 Retry-After 取 0～60 秒并与本地退避取较大值；每次真实请求计入预算。
`runtime.vision_min_interval_seconds` 可配置视觉请求启动间隔，缓存不等待；
生成模型并发与图片处理并发分开显示。鉴权错误不重试。
智谱已知余额、周期额度、套餐和权限错误显示业务码，本轮停止发送其余未缓存图片，
并列为待确认。具体策略见 [P2 图片证据](../P2/07_图片证据.md)。
持续限流不能靠重试保证成功，应检查服务商额度/限额。
读取失败的图片进入待确认清单，不计为已理解；缓存命中不发送请求。

PDF 的 `FontBBox` 缺失提示通常不阻止正文解析。同一次解析仅显示首次提示，
并在问题清单中记录总次数；其他库警告继续显示，表格和文字定位仍需人工核对。

| 显示 | 排查 |
|---|---|
| models.llm / models.embedding 未配置 | 填写该服务真实模型、地址和 api_key |
| 密钥未设置 | 填写本地配置的 api_key；使用 api_key_env 时检查当前进程环境，不发送密钥给调试者 |
| HTTP 400 / 404 | 核对模型、地址、API 协议及输出格式；向量服务不是生成接口 |
| HTTP 401 / 403 / 429 | 查看服务商的密钥权限、额度和限流；必要时降低并发 |
| 生成模型 HTTP 402 | 账户余额不足，充值或更换有余额的密钥后恢复；更新智谱密钥不会补充 DeepSeek 余额 |
| 向量模型 HTTP_429_BIGMODEL_1113 | 智谱账户欠费，立即停止重试；恢复余额后再构建 RAG 索引 |
| 预算不足 | 按提示核对完整输入估算，调整预算或分块，不静默丢弃核心依据 |
| 模型输出被截断 | 调整 models.llm.max_output_tokens 或减小批次；增加输入预算无效 |
| 单个测试点用例数量超过上限 | 核对 generation.max_cases_per_point；超限应进入有界结构修复，不靠提高上限掩盖模型输出问题 |
| 图片解释 HTTP_429 | 检查视觉服务限额；重试耗尽的图片进入待确认，不算成功 |
| 运行版本或配置变化 | 使用保存测试点时的配置；变更后重新执行完整流程 |

已知流程错误直接展示固定说明；未知第三方错误只展示异常类型。
索引/检索失败会停止生成。重排失败仍可使用已有召回排名，其降级单独记录。
用 `status 运行ID` 查阶段，`inspect 运行ID --stage retrieval` 查检索记录。
`inspect 运行ID --stage invocations` 的 validation_errors 映射保存过滤后的结构诊断，
终端只显示前三条；未知字段名用占位符，错误输出值不回显。

提炼失败且已保存分块时，可用原命令追加 `--resume 原运行ID --from-stage extract` 恢复；
提炼全部完成后，使用 `--from-stage plan_points` 从规划继续。文档内容、配置与提示词必须
一致；密钥值不进入配置快照，补充余额或更换同服务密钥不影响一致性检查。
恢复提炼会复用父运行中同请求指纹的成功批次。未指定恢复时不会复用其他运行的提炼结果。

如果智谱免费视觉模型持续返回 1305，可在 `models.vision.model` 选择有权限的付费型号
`glm-4.6v-flashx`，并设置 `thinking_mode: disabled` 减少推理等待；费用及限额以账户为准。
模型或思考参数变化会产生独立图片缓存，不能将旧模型结果算成新模型的调用成功。

审核代码与测试文件统一列在 [RAG 主线说明](../P2/README.md)，避免多份清单相互过期。
