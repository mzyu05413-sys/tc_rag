# P1.8 原文依据与用例生成

[返回学习导航](../README.md) · [P1 总览与完整命令](01_功能架构与流程.md)

## 先理解目的

模型必须看到当前测试点的依据，避免只凭标题补造业务。

## 输入和输出

当前运行的有效测试点、规则、证据及用例 Skill → CaseBatch。

## 处理流程与代码阅读

从 SQLite 当前运行快照组装直接证据及关联功能上下文；按点分批；超预算或截断时缩小批次。限制每点用例数。

先读 `src/tc_rag/application/orchestration/pipeline.py` 的入口及中文注释，再沿其调用进入端口和领域模型。文件路径从项目根目录起算。

## 用一个例子理解

299、300、301分别成例；明确动作、输入与可观察预期，不编造错误码。

## 验证和审核

自动验证见 `tests/integration/test_pipeline.py`。审核时沿“原文 → 规则 → 测试点 → 步骤预期”反向查一次，确认每个结论都能找到输入依据。

## 当前边界

所有正式生成都使用 [RAG 上下文](../P2/06_上下文与生成.md)。原文依据始终保留，检索结果补充条件和例外。Skill 只读取指定 Markdown，不执行包内脚本/附件。
