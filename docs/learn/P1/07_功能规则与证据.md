# P1.6 功能与规则提炼

[返回学习导航](../README.md) · [P1 总览与完整命令](01_功能架构与流程.md)

## 先理解目的

把自然语言整理为有原文依据、能独立追踪的规则。

## 输入和输出

Chunk 与原文定位 → EvidenceSpan、Feature、RequirementRule、Issue。

## 处理流程与代码阅读

模型先提出候选；本地核验引文与定位，拒绝无效引用；只保守归并精确重复，保留候选到最终规则的 rule_mapping。条件不同不强行合并。

先读 `src/tc_rag/application/services/design.py` 的入口及中文注释，再沿其调用进入端口和领域模型。文件路径从项目根目录起算。

## 用一个例子理解

模型写最多301个，而原文是最多300个，应被引文/依据检查拦截或标记。

## 验证和审核

自动验证见 `tests/unit/test_design.py`。审核时沿“原文 → 规则 → 测试点 → 步骤预期”反向查一次，确认每个结论都能找到输入依据。

## 当前边界

引文存在不证明规则解释正确；模糊等价归并尚不自动执行。首先人工对照前20条规则。
