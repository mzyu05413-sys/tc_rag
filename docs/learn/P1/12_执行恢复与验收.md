# P1.11 端到端、恢复与验收

[返回学习导航](../README.md) · [P1 总览与完整命令](01_功能架构与流程.md)

## 先理解目的

把独立服务串成一次连续执行的 CLI，并保留失败位置和可复用事实。

## 输入和输出

文档路径、指令、可选 Skill、输出目录 → 测试点目录 XMind、用例 Excel 和报告。

## 处理流程与代码阅读

`generate()` 调用 `points(publish=False)` 保存各阶段事实，再直接调用 `cases()`。
失败保存阶段和异常类型；`extract`/`plan_points` 支持基于原运行创建新运行恢复。
用例阶段失败可用 `cases RUN_ID` 从 SQLite 事实重试，无需原文或脑图回传。
配置快照需一致；自定义 Skill 路径也要保持一致，内容指纹影响生成缓存。

先读 `src/tc_rag/application/orchestration/pipeline.py` 的入口及中文注释，再沿其调用进入端口和领域模型。文件路径从项目根目录起算。

## 用一个例子理解

`start` 交互输入，或 `run 文件 -i 指令` 一次完成。只传文件、不传 instruction 仍为预览。
已成功交付后再生成会创建新批次，XMind 和 Excel 仍在同一目录。

## 验证和审核

自动验证见 `tests/integration/test_pipeline.py、tests/live/test_rag_live.py`。审核时沿“原文 → 规则 → 测试点 → 步骤预期”反向查一次，确认每个结论都能找到输入依据。

## 当前边界

不是任意阶段 DAG 续跑；真实模型、gold质量基线和 XMind 桌面验收仍待人工。
