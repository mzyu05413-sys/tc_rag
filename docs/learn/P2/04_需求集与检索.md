## 为什么先确定范围

语义相似不代表属于本次需求。RequirementSet 当前由单份文档内容指纹确定，运行 index 快照绑定需求集、空间、manifest 和索引版本。检索只在本次证据集合内评分；外部文档的直接证据 ID 会被拒绝。

`Pipeline._retrieval_evidence()` 汇总有效提炼证据与 ChunkSource 对应的原文字符区间。原文片段保留 Block、locator、origin，帮助找回提炼时没有选中的背景，不会自动成为 RequirementRule。

## 查询与记录

`RagContext.retrieve()`：查询向量缓存/生成 → 范围内向量搜索 → 可选关键词/RRF → 可选重排 → 补充证据组装。

```powershell
pip install -e '.[keyword]'
# 配置 retrieval.keyword_enabled: true
```

jieba 分词后的词频单独召回；与向量结果分别排序，再按 `1/(60+rank)` 做 RRF。vector_hits 保留原始度量分数，fusion 单独记录 RRF 分数，不混加两种原始分数。

```powershell
tc-rag inspect RUN_ID --stage retrieval --config workdir/local.yaml
```

bundle 包含 query_id、scope、space_id、index_version、命中/排名、关键词、融合、重排状态、直接/补充证据和查询缓存命中。计时为 query_embedding_ms、candidate_search_ms、rerank_ms、context_build_ms；最后一项还包含预算组装开销。

## 验证和限制

`test_cache_and_document_scope` 验证换文档不串证据；关键词测试验证范围和 RRF 公式；完整 CLI 测试验证测试点规划和用例生成都参与检索。

默认不设绝对相似度阈值。不同度量、模型和融合分数不能共用阈值。多文档、子集与跨文档冲突在 P4 扩展。
