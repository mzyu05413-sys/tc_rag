# P2.5：重排适配与降级

[返回 P2 总览](README.md)

## 重排职责

检索提供候选；rerank 再读“问题 + 有限候选文字”调整顺序。它不增删规则，也不能把文字变成已确认需求。默认关闭，是否启用取决于人工评估的质量与成本收益。

## 协议和配置

HttpReranker 按[智谱官方文本重排序接口](https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E6%96%87%E6%9C%AC%E9%87%8D%E6%8E%92%E5%BA%8F)实现。核对日期 2026-10-25，未调用真实服务。

```yaml
models:
  rerank:
    enabled: true
    adapter: http
    base_url: https://open.bigmodel.cn/api/paas/v4/rerank
    model: rerank
    api_key: ""  # 只在 workdir/local.yaml 填智谱密钥；不进入快照或导出
    api_key_env: TC_RAG_RERANK_API_KEY
retrieval:
  rerank_top_n: 6
```

base_url 是完整 REST 地址。请求 model/query/documents/top_n；响应 index 映射回候选，以 relevance_score 排序。当前协议至多 128 候选，查询和单条文本至多 4096 字符；超出则降级，不静默截断文本。

## 故障和验证

RagContext 只重排前 rerank_top_n 候选，其余保留。超时、HTTP 错误、重复/越界索引、非法分数或候选集合改变，都会回退原召回排名，bundle 记录 fallback 和 error_type，不记录供应商异常正文。

`test_p2_adapters.py` 验证字段、排序、超时、非法索引/分数；`test_rag_cli.py` 用预设重排器跑通 rag+rerank 规划与用例生成。不同厂商需要独立适配器，不能只换 URL 假设协议兼容。
