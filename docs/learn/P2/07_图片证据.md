# P2.7：基础图片证据

[返回 P2 总览](README.md)

## 范围和配置

处理 DOCX/PDF 解析器已提取的图片，不是整页扫描件 OCR。关闭时保留图片和未解析提示；开启后仍保留图片 Block，在其后增加独立文字 Block。

```yaml
parsing:
  vision_enabled: true
models:
  vision:
    enabled: true
    supports_images: true
    adapter: openai_sdk
    api_mode: chat_completions
    model: 你的视觉模型
    api_key: ""  # 在私有配置填写；留空才回退 api_key_env
    api_key_env: TC_RAG_VISION_API_KEY
runtime:
  vision_min_interval_seconds: 3 # 可选的视觉请求启动间隔；不是服务商配额承诺
```

supports_images 表示部署方已核实能力，启动时检查声明，不按名字猜测，也不远端探测。兼容端点需填 base_url。

## 流程和代码

OpenAICompatVision 用 Pillow 转 RGB、最长边 1600、PNG 编码，发送图片和章节上下文。`prompts/vision/v1.md` 要求只描述可见需求，看不清就说明，不推断。

VisionEvidenceService 缓存键包括图片 hash、模型/端点、预处理参数及版本、提示词版本及指纹、章节上下文。派生 Block 保留定位、processing_model、processing_version 和 origin=vision。

视觉端点显式设置 max_output_tokens 或非默认 thinking_mode 时，这些参数也进入缓存标识；
保持默认参数时兼容原有缓存。max_output_tokens 发送为 Chat 接口的 max_tokens，
thinking_mode 仅用于明确支持思考开关的服务。

图片目前由服务层逐张处理，启动时显示的生成模型并发数不影响这一步。
`runtime.vision_min_interval_seconds` 控制视觉真实请求的启动间隔，默认 0；
本地遇到频繁限流时可先设 3 秒，再按账户实际限制调整。它不改变缓存键。

临时 HTTP 错误（含 429）、连接及超时按 `runtime.max_attempts` 有界重试，
每次实际请求均计入预算。连续 429 的冷却按 10、20、40、60 秒递增，
上一张图片重试耗尽后的冷却仍约束下一张；成功后重置连续限流计数。
秒数形式的 Retry-After 取 0～60 秒，和本地退避取较大值；其他临时故障仍使用短指数退避。
排队和冷却可用 Ctrl+C 取消，等待本身不记为模型调用。

智谱端点只提取四位业务错误码，不输出响应正文。1302 表示账户速率限制，1305 表示服务繁忙。
1113、1308、1310 等余额、周期额度错误，以及已知套餐/权限限制，不做短暂重试；
本轮其余未缓存图片停止发请求并逐张列为待确认，已成功的缓存仍可复用。
这项账户错误识别只适用于 `open.bigmodel.cn`，不会套用到其他兼容服务。
具体含义见[智谱错误码](https://docs.bigmodel.cn/cn/api/api-code)，
账户限额见[官方速率限制说明](https://docs.bigmodel.cn/cn/api/rate-limit)。

终端逐张显示结果并汇总总数、成功数、缓存数及失败数，持续限流仍须处理服务商限制。
同一文档、章节和视觉配置重跑会复用已成功图片；失败结果不缓存，运行 ID 会重新创建。
缓存复用不是任意阶段断点续跑，也不代表图片业务含义已通过人工审核。

提炼时应用层按 Block 写回来源，模型不能把图片解释标成原文。EvidenceSpan 的 uncertain 为 true；核验要求来源、处理信息、定位和引文一致。进入检索后也保持这些标记。

## 验证和人工检查

测试验证缓存、换模型失效、来源核验、图片 HTTP 请求和能力声明，以及限流重试、请求预算、取消和失败汇总。失败进入 unparsed；成功仍提示人工核实。解析器原有图片未解析记录也不会自动当作已通过验收清除。

人工至少核对 3 张图：数字、角色、连线、条件是否读对，有无猜测隐藏交互；不确定信息不应成为确定断言。扫描页提取、完整 OCR 和复杂图结构留到 P4。
