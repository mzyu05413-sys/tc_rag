# P2.2：向量空间与缓存

[返回 P2 总览](README.md)

## 目的和输入输出

embedding 将原文和检索问题变为数值向量。输入是有序文本列表及 EmbeddingSpace；输出 EmbeddingBatch 必须与输入一一对应。向量只帮助排序候选，不能证明业务事实。

空间由供应商地址、模型、维度、归一化、输入模板版本共同确定。换模型、地址、维度或模板会换空间，不会命中旧缓存。配置维度是校验预期，不会自动要求所有供应商降维。

## 智谱配置示例

在私有 `workdir/local.yaml` 中合并以下字段；保留原有 `models.llm`，不要重复创建第二个 models 或 retrieval 节点。核对日期 2026-10-25，未调用真实服务。

```yaml
models:
  embedding:
    enabled: true
    adapter: openai_sdk
    base_url: https://open.bigmodel.cn/api/paas/v4/
    model: embedding-3
    api_key: ""  # 填智谱 API Key；仅保存在被 Git 忽略的本地配置
    batch_size: 16
    concurrency: 2
  rerank:
    enabled: true
    adapter: http
    base_url: https://open.bigmodel.cn/api/paas/v4/rerank
    model: rerank
    api_key: ""  # 可使用具有对应权限的同一智谱 API Key
retrieval:
  embedding_dimension: 2048
  rerank_top_n: 6
```

官方 [Embedding-3 说明](https://docs.bigmodel.cn/cn/guide/models/embedding/embedding-3) 和 [文本嵌入 API](https://docs.bigmodel.cn/api-reference/模型-api/文本嵌入) 指定模型名 embedding-3，默认输出 2048 维。当前适配器未发送 dimensions 参数，因此使用默认 2048；只改本地 embedding_dimension 不会让服务返回 1024/512 维。

embedding 的 base_url 是 SDK 服务根地址，SDK 自动追加 embeddings；[rerank API](https://docs.bigmodel.cn/api-reference/模型-api/文本重排序) 使用完整 REST 地址，模型名为 rerank。生成模型、向量模型和重排模型可来自不同服务，分别填写各自的密钥。

非空 api_key 优先，留空时才回退 api_key_env。密钥从序列化中排除，不进入运行/索引快照、数据库、诊断配置及导出；诊断配置属于可分享的无密钥记录，不能直接当作凭据备份。

保存后执行 `tc-rag doctor` 做离线检查，再执行 `tc-rag start`。离线通过不证明远端权限或连通性。`doctor --live` 只检查首轮 RAG，主动关闭 rerank/vision；要验收重排，需在正常运行的 retrieval 快照中看到 rerank.status=succeeded，fallback 表示已降级，不能视为重排成功。

## 流程和代码

1. `RagContext.prepare()` 收集去重文本，先检查 SQLite 缓存。
2. `OpenAIEmbedder.embed_batch()` 按 batch_size 分批，在并发信号量内发送请求。
3. 响应按 index 重排，拒绝缺失、重复、维度不符和非有限数。
4. 按空间要求归一化，零向量不能归一化。
5. 缓存保存到 embedding_records；读取时校验文本、空间、向量指纹和维度。

缓存键包含空间 ID 和文本。索引业务对象另外通过 SQLite vector_ids 表映射到唯一 int64，不把 UUID 截断成整数。相同文本可以复用向量，同时保留各自业务定位。

429、连接异常、超时和可重试服务错误有界重试；鉴权错误立即失败。每次实际请求记录 ModelInvocation：耗时、模型、usage 和错误类型。生成、embedding、rerank、vision 共用调用预算；缓存命中不新增模型请求，未知 usage 保留 null。

## 验证和限制

`test_rag.py` 验证乱序、缺失/重复 index、缓存及换空间；`test_p2_adapters.py` 验证重试、预算共用、缓存损坏和禁用缓存。默认测试只走 MockTransport。

人工检查同一批文本第二次运行是否没有新 embedding 调用，再换模型名观察重算。端点必须具有兼容 embedding 协议，不自动换供应商。
