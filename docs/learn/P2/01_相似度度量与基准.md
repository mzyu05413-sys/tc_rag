# P2.1 相似度度量与基准

## 为什么先做这个

RAG 会把查询和证据编码成向量，再按分数找候选。先把“分数是什么、越大还是越小相关”定义清楚，后面才能正确替换 NumPy/faiss 后端。本模块只计算向量分数，不发模型请求；当前由索引层调用，并接入正式 RAG 流程。

## 输入输出和分数含义

`get_metric(name).score(query, matrix)` 接收一个非空一维查询、一个二维候选矩阵，返回与候选行顺序一致的一维分数。空候选可以是 `[]` 或形状为 `(0, 维度)` 的矩阵。

| 名称 | 运算 | score_kind | 排序 |
|---|---|---|---|
| cosine_math | 逐条用纯 math 计算余弦，作为对照 | cosine_similarity | 越大越相关 |
| cosine_numpy / cosine | NumPy 批量余弦 | cosine_similarity | 越大越相关 |
| euclidean | 差向量各分量平方和，不开方 | l2_squared | 越小越相关 |
| dot | 原始向量内积，不自动归一化 | inner_product | 越大越相关 |

例如查询 `[1,0]`、候选 `[2,0]`，余弦为1、内积为2、平方距离为1。分数不能直接混合相加，也不能因为数值大就跨度量比较。归一化后才满足 `平方距离 = 2 - 2×余弦`。

## 代码流程

读 `src/tc_rag/infrastructure/retrieval/metrics.py`：`SimilarityMetric` 约定方法和排序元数据，`get_metric()` 选择实现。首先检查形状、维度和有限数，再计算分数；本步不排序、不做 top-k，候选行与分数对应关系保留给索引层处理。

余弦要求查询和每个候选都不是零向量，包括空候选时也会检查查询。归一化先除以最大绝对值，避免极大或极小有限数在求模时溢出。内积和平方距离允许零向量，但结果超出浮点范围时明确报错，不返回 inf 参与排序。

```python
from tc_rag.infrastructure.retrieval.metrics import get_metric

metric = get_metric("euclidean")
scores = metric.score([1.0, 0.0], [[2.0, 0.0], [0.0, 1.0]])
# scores 为 [1.0, 2.0]；越小越相关，所以第一个候选更接近。
```

## 如何验证

```powershell
$env:PYTHONPATH = 'src'
python -m pytest tests/unit/test_metrics.py -q
python scripts/bench_similarity.py --output workdir/dev/benchmarks/similarity.json
```

基准默认固定种子42，候选1000条、维度128、查询批量4、预热1次、重复3次。显示整批查询的中位耗时，JSON 还记录每次样本、Python/NumPy版本和系统信息。批大小表示连续计算多少个查询，不是异步网络并发数。余弦两种实现不一致会直接失败。

性能数字只属于该机器和数据规模；不能据此宣称 RAG 准确率提升或大型索引性能达标。
