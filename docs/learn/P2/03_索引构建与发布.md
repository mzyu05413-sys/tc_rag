# P2.3：索引构建与发布

[返回 P2 总览](README.md)

## 索引与数据库

SQLite 中的证据、空间、缓存和 manifest 是事实；索引保存 float32 连续矩阵，是可重建文件。版本指纹包含业务 ID 顺序、向量、空间和度量，错配 ID、维度或度量会被发现。

NumpyIndex 是默认精确后端；可选 FaissIndex 使用 IndexIDMap2 + IndexFlatIP/IndexFlatL2。余弦先归一化；内积按大到小，平方 L2 按小到大。FAISS 使用数据库分配的 int64 ID 映射回业务对象。

## 发布和查询

```text
构建独立 candidate → 校验 ID/数量/维度/数值
→ ArtifactStore 临时文件及原子写入
→ 读回检查 checksum、矩阵与版本指纹
→ 写 index_manifests → 更新运行 index 快照活动指针
→ 切换内存活动索引
```

`RagContext.prepare()` 最后才切换索引对象；写盘或校验失败，保留旧 generation。文件不用 pickle，FAISS 从受管理且校验过的矩阵重建，不读取任意外部二进制。

范围过滤发生在 top-k 之前。NumPy 只对允许行评分；FAISS 为允许集合构建临时精确索引。空范围返回空，候选不足返回实际数量，并列允许两个后端顺序不同。

```powershell
pip install -e '.[faiss]'
# 配置 retrieval.backend: faiss
```

未安装 FAISS 仍可使用 NumPy；选择 FAISS 而未安装会报错，不静默切换。

## 验证和限制

`test_rag.py` 验证保存加载、错配 manifest、损坏文件拒绝；`test_p2_adapters.py` 比较三个度量下 NumPy/FAISS 的命中和分数、范围、空索引及发布失败保留旧 generation。

不承诺 FAISS 更快；临时 Flat 的开销需要实测。ANN、完整 DAG 恢复和孤立文件回收在后续阶段处理。
