tc-rag 完整运行逻辑

通用控制流：入口 → 配置与装配 → 解析/视觉 → 分块 → 提炼 → 索引 → 测试点 → 用例 → 校验 → 导出。含判断分支、循环与失败路径。

入口/结束 判断 处理步骤 降级/标记 失败终止

1入口与前置检查

CLI 命令
run · start · cases · doctor · status · inspect · export · evaluate · estimate
↓
加载配置
内置默认 → YAML（--config / workdir/local.yaml / config/defaults.yaml）→ 环境变量 → CLI 覆盖；Pydantic 校验；密钥仅以环境变量名引用或走 SecretStr
↓
命令类型？
只读命令
status / inspect / export / evaluate
只读 SQLite 快照与业务表，不创建模型客户端、不产生费用；export 从事实重建派生文件
输出结果后结束
执行类命令
run / start / cases / doctor
start 交互采集文档路径与指令后复用 run；cases 从已保存测试点重试用例生成
仅预览？（--preview）
是 → 输出阶段计划
不解析、不调用模型、不写运行数据
否 → 继续
↓
校验运行配置 validate_runtime_config
密钥是否可取、模型能力是否匹配（vision 需 supports_images）、scan_policy 是否在支持范围；失败即启动错误
↓
装配 build_pipeline
加载 prompts/stage/v1.md（extract、plan_points、generate、rag_context、vision、case_skill）；generate 追加内置 skill 与用户 skill；构造 Repository、ArtifactStore、LLM、Embedder、VectorIndex、Reranker(可选)、Vision(可选)、Exporter；录制每次模型调用
↓
创建 Run（status=running）
run_id 为不透明标识，写入 config_snapshot

2准备阶段：续跑 / 接入 / 解析

--resume <run_id> ？
是 · 校验一致
一致性检查
配置快照相同、生成指令相同、文档内容 hash 相同；任一不符即拒绝恢复
存在父运行的 chunk 快照？
是 → 直接复用 blocks / chunks / issues
跳过解析与分块
否 → 重新解析
已完成页命中 pdf_page:n 检查点；已转写图片命中视觉缓存；仅补算缺失部分
否 · 全新运行
ingest
校验路径/格式/大小 → 内容哈希 → 复制到 assets/<hash> → 登记 Document 与 Asset（同 hash 复用）
写 input 快照
指令 + 文档指纹；保证解析中途中断也能安全续跑
解析 parse
PDF：逐页取文字块/坐标/页码/表格候选/图片；DOCX：按文档顺序取段落/表格/图片锚点
↓
逐页循环（PDF）
该页检查点已存在？
是
复用页结果
恢复 blocks / assets / issues / 跨页状态（标题层级、全局序号、问题计数）
否
解析本页并写检查点
空白/扫描页 → 记 unparsed Issue，不生成业务块
↓
视觉转写开启？（vision_enabled）
否
跳过图片
在报告中列明被跳过的图片范围
是
全部页完成后统一并发转写
按 concurrency 并发；请求间隔与限流冷却；单张失败仅记 Issue，不中断
图片缓存命中？
是 → 复用描述；否 → 调视觉模型
缓存键 = 图片哈希 + 模型 + 预处理参数 + 模板版本
生成 origin=vision 派生块
保留原图定位与处理模型/版本，标记不确定
↓
分块 chunk
按标题/段落/表格与 token 预算切分；小表格整体保留，大表格按行组拆并复制表头；条件与紧邻例外不拆开；每块保存 (block_id, start, end) 来源映射
↓
写 chunk 快照并持久化
blocks、chunks、issues 一并落库

3提炼与规则合并

遍历每个 chunk（worker 数 = llm.concurrency）
模型结果缓存命中？
是
直接取缓存输出
键 = 请求 + 输出 Schema + 模型配置；续跑可复用父运行缓存
否
调用 LLM 结构化提炼
输入 chunk + 标题路径 + 相邻块 + 可引用 evidence 列表；输出 Feature / Rule / Entity / 缺口
输出通过 Schema 校验？
否 → 携带字段错误修复重试（有上限）
超过上限 → 该批失败并取消其余任务
是 → 落库并写缓存
↓
单 chunk 后处理
命名空间化 ID；证据来源取自解析事实（禁止 vision 冒充原文）；引文必须能在本 chunk 的来源区间匹配；引用闭包校验
↓
合并 reconcile
按功能 / 原文范围 / 规则类型 / 结构约束指纹分组：相同规则合并证据；条件不同保留；冲突建 Issue，不覆盖
↓
保存 extract 快照
evidence · features · rules · entities · issues 写入业务表

4向量化与索引

chunk 文本嵌入缓存命中？
是
复用向量
不产生调用；计时标注缓存命中
否
批量嵌入
按 batch_size 分批、按并发上限调用；响应按 index 对齐，校验条数/维度/有限值
↓
构建向量索引
float32 矩阵；显式 int64 vector_id 映射业务 ID；记录 EmbeddingSpace（供应商/模型/维度/归一化/模板版本）；度量与后端固定
↓
发布索引清单 manifest
校验维度/行数/ID 映射/checksum 后再提交活动指针；读取只认已发布版本

5测试点设计

程序先产生确定性测试点
按 Rule.kind 映射方法；结构化约束明确时直接算边界（下界/边界/上界）；精度或单位缺失 → needs_clarification，不猜
↓
按规则批次（batch_point_limit）并发
检索增强开启？
按需求集/空间/度量取候选 → 范围掩码过滤 → 可选重排
重排关闭时跳过；分数不解释为概率
↓
调用 LLM 补充测试点
输入规则批次 + 证据 + 已有程序测试点；禁止引用批次外规则
↓
校验与合并
数量上限、规则引用归属、边界点不合并；探索性建议单独标记
↓
生成测试点目录树
供 XMind 输出；节点与 point_id 绑定
↓
保存 plan_points 快照

7导出、清单与结束状态

导出
XMind（测试点目录）· Excel（用例列 + 测试点/规则/覆盖/问题/未解析附表）· Markdown 评审视图 · JSON 规范格式
导出前清洗
控制字符转义为 \uXXXX；来源文本按文本写入，防公式注入；原始事实不被修改
↓
运行清单 manifest 与 metrics
配置快照（脱敏）、提示词版本与指纹、模型标识、输入文档指纹、阶段耗时、调用数、token；未知用量记 unknown，不记 0
↓
运行结果判定
正常完成
succeeded
partial_failed
有效产物已导出，但存在失败批次或待确认问题
未完成
failed
记录失败阶段与错误类型；已完成检查点保留，可 --resume
cancelled
Ctrl+C；停止投递新任务，保存已完成结果

8失败与降级路径总览

触发行为
配置非法 / 缺密钥启动即失败，错误只提示字段与变量名，不回显密钥
文档不存在 / 格式未启用输入校验失败，不产生运行记录
加密 PDF / 损坏文件解析失败，Run= failed
扫描页 / 文字质量低整页记 unparsed Issue，不进入后续流程
单张图片转写失败记 Issue，其余图片继续
模型输出不合 Schema携带错误修复重试；超限则整批失败
触发行为
上下文超预算拆分批次，不静默截断核心规则
输出被截断返回特定错误，上层缩批或提示提高输出上限
429 限流有界退避 + 尊重 retry-after；不无限重试
401/402/403/1113快速失败并给出中文处置建议，不重试
证据不足标记待确认，不让模型编造来修复
索引缺失 / 损坏拒绝加载，运行停止；可从事实重建

9核心不变式

① SQLite 是唯一事实来源
XMind / Excel / Markdown / 向量索引都是派生视图，可重建，不可反向修改事实
② 一切皆可追溯
用例 → 步骤 → 规则 → 证据 → 原文块与字符区间；vision/ocr 与原文严格区分来源
③ 程序约束、模型表达
程序负责 ID、引用闭包、引文匹配、覆盖矩阵；模型只负责理解与表达
④ 不猜测缺失信息
精度/单位/文案/错误码缺失时留空并建 Issue，不补造
⑤ 自动检查 ≠ 人工批准
validated 仅表示通过当前自动校验
