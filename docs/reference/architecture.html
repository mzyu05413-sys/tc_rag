tc-rag 架构与一次完整运行

需求文档（PDF/DOCX）→ 可追溯证据 → 规则 → 测试点 → 测试用例 → XMind / Excel / 报告

分层：interfaces → application → domain SQLite 为唯一事实来源 示例：48 页 / 14 分 49 秒

1分层架构

interfaces · 入口层

命令行与交互，不承载业务算法
workflow.py runstartdoctor casesstatusinspect exportevaluateestimate
↓

core · 配置

config.py（四层合并 + 校验） defaults.yamllocal.yaml环境变量
↓

bootstrap · 组合根

校验运行配置、加载提示词与内置 skill、按配置装配真实适配器
build_pipeline()validate_runtime_config() prompts/{extract,plan_points,generate,rag_context,vision,case_skill}/v1.md
↓

application · 应用层

阶段编排、快照、续跑；外部能力只经 ports 访问
orchestration/pipeline.py services/ingestchunkingdesign visionevaluation ports/contracts.py
↓ 依赖 · 协议实现 ↓

domain · 领域层

纯业务对象与规则，不导入 SDK / sqlite3 / 文件 IO
models.pypipeline.py rag.pyreview.pyidentity.py

infrastructure · 基础设施层

实现 ports：解析、模型、检索、存储、导出、运行时
parsing/pdf · docx providers/openai_sdk · embedding · rerank · vision retrieval/metrics · index · context storage/sqlite · files exporters/reports · xmind runtime/timer · tokens

2一次运行的执行流程

122.5s（含视觉）
3

全部页解析完后统一并发转写 52 张图片，生成 origin=vision 派生块
52 次调用

chunk
按标题/段落/表格与 token 预算切分，保留到原文块的字符区间映射
0.3s
5
extract
每个 chunk 调 LLM 提炼功能/规则/证据，再合并去重
371.9s
76 个 chunk → 171 次调用：其中约 95 次是 schema 失败后的修复重试（SchemaOutputError 35 次）

87 次调用 → 887 个测试点（ready 592 / needs_clarification 295）
8

256.0s

4并发、缓存与断点

环节策略检查点 / 缓存
parse逐页顺序（纯 CPU，开销小）run_id:pdf_page:n 每页检查点
visionasyncio.gather + 适配器信号量（8），跨页统一执行rag_records 图片哈希 + 模型 + 模板
extractworker 数 = llm.concurrency（8）run_id:cache:<fingerprint>
plan / generateworker 数 = llm.concurrency（8）同上，续跑可复用父运行
embeddingembedding.concurrency（2）文本指纹缓存
rerank开关控制；关闭时不产生调用不缓存，检索内联
export单线程，从 SQLite 重建可用 tc-rag export <run_id> 重导
成功路径 需人工核实 / 可重建 本次失败
