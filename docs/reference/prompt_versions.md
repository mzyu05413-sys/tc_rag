## 2026-10-28 `plan_points` 待澄清口径收紧

当前保留的 `prompts/plan_points/v1.md` 包含以下两条约束：

- 只有缺少生成该测试点所必需的参数（数值、角色、状态、触发条件）时，才使用 `needs_clarification`；
- 仅界面文案、提示语或实现细节未写明时，使用 `ready` 并在 `issues` 中说明，不标记为待澄清。

目的：减少模型补充测试点过度标记待澄清。该修订不改变输出 Schema 或业务规则，
真实模型上的待澄清比例需重新运行后抽样验证；改动后的提示词指纹随运行 manifest 记录。

|---|---|---|

| `prompts/vision/v1.md` | 只描述图片可见需求，记录不确定性 | HTTP 模拟、来源和缓存验证；图片准确性待抽查 |

`bootstrap.py` 将 rag_context 组合到规划和生成提示词，并将 case_skill 加入生成提示词。
各阶段统一加载表中的 v1 资源；不再按代码参考开关选择试验提示词。
manifest 记录各资源及组合后指纹；指定 `--skill-file` 或 `generation.skill_file` 时追加自定义规范，
改变 generate 缓存依赖，另存内置/自定义校验和及接入方式快照。

Skill 只作为用例生成规范，不执行脚本或附件，不能覆盖原文依据和输出 Schema。提示词版本相同但组合文本或指令不同，不能认定是同一次输入；恢复和缓存必须遵守实际指纹及配置约束。

已有离线验证不代表提示词已在真实文档上达到业务标准。真实使用需抽查遗漏条件、例外、无依据预期及重复；评估标注用于测量效果，不是中间审批步骤。
