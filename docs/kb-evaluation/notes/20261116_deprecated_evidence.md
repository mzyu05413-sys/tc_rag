# 删除线与检索证据的边界

原文保存与有效检索是两件事。直接删除原文会让旧引用偏移失效；只保留原文又会让作废规则进入检索。因此Block保存完整文字和作废区间，Chunk只引用未作废的原文切片。

区间采用左闭右开 `[start_char, end_char)`。DOCX表格保存JSON，必须对编码后的字符计算偏移：换行、双引号和反斜线不能按视觉长度计数。分块文本由来源切片用换行连接，删除两侧不直接拼成新句。

验证分成三层：原文保真；每个Chunk可以从来源区间准确重建且不与作废区间相交；作废引文不能通过证据校验。以上均通过，仍不代表业务语义完整，例如删掉“默认开启”不能推导出“默认关闭”。

直接run删除线已支持；样式继承与修订删除目前告警，Vision重复旧正文仍需单独控制。旧快照不会因代码升级自动清洗。重建后应复核金标映射，不能把不同快照的指标直接归因于检索算法。

## 重排同分的解释与实现

模型返回同分时，最终名次还包含同分处理策略的影响，不能只凭第16/17名就说模型给证据更低分。当前适配器增加显式同分策略：默认沿用服务行顺序，可选择按原输入index保序；不舍入、不把近似分数合并。保序仅利用既有检索排名，不创造新相关性信息。

用保存分数和MockTransport回放，可验证实际适配器是否实现同一策略，无需重复付费。但回放不是新模型采集，开发集上的改善也不是独立留出结论。全局配置涉及两条RAG路线，所以实验应优先使用一次性的CLI覆盖。
