## 接下来只做这四步

1. **新任务草稿已准备。** 六项分别为线索下拉字段配置、线索池维护与领取回收、客户查重与权限展示、联系人资料维护与启停、公海客户领取与分配、商机阶段推进与完结。共30规则、39正文锚点；未查看新任务检索结果。原件正文/定位和直接删除线核对通过，锚点片段与开发正例及本批其他任务无交集；完整语义与图片相关集合仍待核对。
2. **审核并冻结金标。** 用户确认业务歧义；助手完成显式检索范围内全部片段的相关性预标和图片来源核对，未知保持null。采纳后冻结题目、金标、范围和排除规则，再开始运行。
3. **同一新题集比较A/B。** 金标发布后，用户执行新问题embedding和固定池重排采集；助手完成离线召回、材料核验和评分。同一问题、向量、范围、重排模型和k，不根据结果调整权重、模型、输入或分块。不得拿不同题集分数变化宣称算法提升。
4. **形成选型与最终报告。** 联合比较必要规则覆盖、逐题遗漏、图文P/R/F1、宏微差异和返回噪声；记录服务失败及有效样本数。未约定业务阈值，不虚构“达标”。如果结果接近或互有优劣，如实保留条件性结论。

新功能可以来自当前六份已见PRD，但这属于固定语料上的独立功能验证，不是未见文档泛化。已在开发中分析过的同义规则不能通过改写题目进入留出验证；同一证据片段含多个共享规则时须保守隔离。

验证结果如果用于继续改k、权重、模型或输入，这批数据就转成开发数据，不能继续宣称它提供独立验证结论。新任务当前只是split=test的待审核候选，完整金标尚未发布，没有新查询向量、重排调用或验证分数。
