# 向量入库失败与图片缓存恢复

本轮只进行离线检查与测试，没有调用真实模型，未修改本地视觉模型、思考模式或复核配置。

## 已核实事实

失败任务状态为 EmbeddingProviderError，记录含 HTTP_400_BIGMODEL_1210，知识库尚无发布快照。六份 PRD 的 184 张图片全部通过原缓存键审核，缓存限定且禁止读模型的离线重建成功。

原分块共 310 条，最长 9347 UTF-8 字节；保源细分后 463 条，每条不超过 3000 字节。原文、图片结果及原 Block 不截断，新的检索片段绑定原字符区间。该统计是离线重建，尚未执行真实向量请求确认 400 已消失。

官方 Embedding-3 页面技术参数列出请求 3072 Tokens 与数组最多 64 条，页面顶部另标 8K。适配器以 3000 UTF-8 文本字节作为保守的文本请求预算，避免依赖其他模型 tokenizer 精确拟合智谱计数。此为字节预算，不声称一个字节等于一个 token。来源 https://docs.bigmodel.cn/cn/guide/models/embedding/embedding-3 ，核对日期 2026-11-12。

## 修复

- 正式 CLI 入库先以小文本验证 embedding 和返回维度，再进入图片处理。该预检绕过向量缓存，实际验证当前端点和凭据；只在用户显式 --live 后发生。
- 模型适配器按文本字节和及条数双重切批，单条超限在联网前拒绝。embedding-3 默认保守预算 3000，其他模型可显式配置 models.embedding.max_input_bytes。默认空值不改变历史快照序列化。
- 知识库在向量化前细分超限片段，保留 Unicode 字符及完整来源区间，不用截断或平均向量掩盖超限。
- --cached-vision-only 强制复用原图片缓存。任意缺失直接抛出错误停止，不能降级为空图片证据，也不能补调用视觉模型。这个运行开关不加入缓存身份。
- 对缓存内容的离线审核复用了真实解析器和原 Vision 服务，视觉 reader 被替换为禁止调用。审计只输出数量和长度，不导出真实原文。

## 用户操作

完整离线回归 825 passed、2 skipped，Ruff 与 Mypy 114 源文件通过；预检绕过缓存与缓存限定边界经定向复测验证。本轮没有真实模型请求，184 张图片缓存离线审核全部通过。

保持当前视觉配置及源文件，用以下命令保护性重试。该命令会由用户主动调用 embedding，图片阶段仅允许读取缓存。

```powershell
.\.venv\Scripts\python.exe -m tc_rag.interfaces.cli kb ingest cordys --source-dir workdir/kb/sources/cordys --cached-vision-only --live
```

如向量预检失败，图片阶段不启动。如缓存身份不匹配，命令停止，需先核查配置及文件变化。成功后用 kb list cordys 确认已发布快照。本轮不宣称重新入库成功。
