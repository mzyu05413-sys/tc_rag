# 首批问题如何人工标注

先打开 workdir/kb/evaluation/annotations/approval_pilot_draft_v1/review.md。JSONL 是程序交换稿，人工可以另写 UTF-8 Markdown 或文字反馈，由助手整理后再次确认。原草稿保留，不直接覆盖。

## 每题填写五项

1. 问题是否合理。可保留、修改或删除，并说明意图。采用测试设计视角，但答案首先是需求条件与规则。
2. 可回答性。填写“可回答”“部分可回答”“无答案”“存在冲突”或“待核对”。无答案必须在题目指定范围内查找后确认。
3. 全部必要证据。复制最小但足够的原文，记下阅读稿 Block ID。相关条件和例外分处不同块时都要列出。同一事实的重复表述记为替代证据。
4. 答案要点。用一条一事实的短句描述必须回答的内容，保留前置条件、默认值、例外及适用版本。缺失信息说明缺失，不能按经验补写。
5. 审核状态和人。未核对为 pending，核对后为 reviewed；有分歧进入仲裁。候选证据只是预筛，不等于已标相关。

证据相关性采用 2 核心、1 辅助、0 不相关，未知为 null。核心直接支持必要答案，辅助提供上下文。标完候选后仍须检查其他段落，未完成完整性审核的题不能计算正式 Recall。

## 可直接复制的填写格式

```text
题号：approval_pilot_11
问题修改：保留 / 修改后的问题
可回答性：
核心证据：Block ID + 原文
辅助证据：Block ID + 原文 / 无
答案要点：
范围完整性：已查完本题指定文档 / 尚未查完
冲突或疑问：
审核人：
```

比如审批人撤回题，不能只标“支持撤回”。若 PRD 写明开关、已同意、后续审批人尚未审批和默认状态，应分别标为必要要点。这里仅说明标法，实际内容须以 PRD 原文核对为准。

首批题范围目前限定审批流文档，先在该文档标注；扩展到六份全库时另行补查相关证据，不能直接复用单文档完整性结论。来自不同时期文档的冲突保留来源，不自行合并为统一业务规则。官方手册辅助核对，手册独有事实不作为 PRD 必答内容。

你先标前五题，我负责把引文核对为 Block 内 [start_char,end_char) 字符区间、校验来源哈希并整理版本化标签，再交你确认。试标阶段无需手工计算字符偏移。
