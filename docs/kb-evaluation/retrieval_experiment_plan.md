# R0～R3 知识库检索实验方案

2026-11-15后续工作以[改进协议v2](retrieval_protocol_v2.md)为准：统一片段级P/R/F1，先扩样和多k，再BM25与固定池rerank。下文为历史阶段协议，不直接作为当前实施命令或指标定义。

版本 v1.1，日期 2026-11-12。状态为待试标确认的实验协议。v1.1 采纳人工语义相关性、答案要点覆盖和分数分布；执行步骤见[流程指南](retrieval_experiment_workflow.md)。

## 1. 本轮目标

以六份 Cordys CRM PRD 的一个已发布快照为固定语料，用小规模人工金标回答检索模式、后端实现和指标计算三个问题。首批 15～20 题，结论限定为试点。来自不同时期的规则保留各自来源。

| 编号 | 性质 | 核心问题 | 产物 |
|---|---|---|---|
| R3 | 指标正确性验证 | 分母、去重、宏/微平均是否正确 | 手算用例、指标实现及测试结果 |
| R0 | 实验底座 | 是否固定数据、查询向量、标签与协议 | 带指纹的材料包、统一运行器 |
| R1 | 检索效果对照 | vector、keyword、RRF hybrid 的差异 | 总体及分层指标、逐题排名、失败案例 |
| R2 | 工程正确性与性能对照 | NumPy/FAISS 的结果、时延及成本 | 一致性报告、性能表和工程解释 |

执行顺序为 R3 → R0 → R1 → R2。本轮不开展问答/拒答评分、Vision 策略对照或六文档干扰的正式对照。现有问答功能继续供日常使用，实验 harness 复用组件，生产检索语义按现有契约运行。

## 3. R3 指标契约

对同一道题及一个 k，记 C 为前 k 中覆盖至少一个必要证据单元且达到重叠阈值的候选数，U 为这些候选覆盖的去重必要证据单元数，G 为全部必要证据单元数。C 和 U 独立计数。同一候选 ID 重复返回视为结果格式错误；多个不同候选重复覆盖同一证据时，U 只计一次。

- P@k = C/k，实际不足 k 的空位保留在分母。
- R@k = U/G。
- 每题 F1 = 2PR/(P+R)，P=R=0 时取 0。
- 宏 P、宏 R、宏 F1 分别对每题对应值取平均。
- 微 P = sum(C)/sum(k)，微 R = sum(U)/sum(G)，微 F1 是微 P 与微 R 的调和平均。

此处 F1 是候选精确率与证据召回率的综合分，不能用一个共享 TP 套分类任务混淆矩阵。字段至少保留 relevant_candidates、covered_groups、total_groups、requested_k、returned_count、irrelevant_returned_count 和 missing_slots。非相关返回数为 returned_count-C，空位数为 k-returned_count，两者分别记录。

固定 k、相同有效问题集时，宏 P 等于微 P。宏 F1 是每题 F1 的平均，不是宏 P 与宏 R 的调和平均。

### 手算核对

| 题 | k | C | U | G | P | R | 每题 F1 |
|---|---|---|---|---|---|---|---|
| Q1 | 5 | 1 | 1 | 1 | 0.2 | 1 | 0.333333 |
| Q2 | 5 | 2 | 2 | 4 | 0.4 | 0.5 | 0.444444 |
| Q3 | 5 | 0 | 0 | 2 | 0 | 0 | 0 |

宏 P=0.2，宏 R=0.5，宏 F1≈0.259259；微 P=0.2，微 R=3/7，微 F1≈0.272727。

额外必测反例为 C=5、U=1、G=4、k=5，此时 P=1、R=0.25、F1=0.4。重复候选不能增加 U。另测一个候选覆盖多个证据、候选不足 k、同一证据的替代区间、重叠边界、多字节字符、无答案和未知标签。

### 可评分集合

相关性完整且 G>0 的 reviewed 题进入主指标。G>0 但无返回，P/R/F1 均为 0。无答案题 G=0 单列，R/F1 等为 null；未审完、待仲裁与未知不按负例计。服务失败单列，配对比较使用两侧都可评分的同一问题集合，并报告排除数。不得只给成功样本的漂亮均值。

命中依据文档哈希、原始 Block ID、半开区间和预登记重叠规则。当前实现按单个候选覆盖金标区间比例判断，默认阈值 0.5；同一候选内的重复来源先合并区间。多个分别未达阈值的候选不自动拼成一次命中。试标后确认阈值，并保存严格阈值敏感性结果。最小事实区间优先于整段标注，避免碰到半段文字就误认为找到完整规则。

MRR 报告截断位置，例如 MRR@10；完整证据命中率判断 U=G。nDCG 只在当前片段集合的候选相关度及理想增益可确定时报告，否则 null。小样本主要描述数值、问题数和案例；问题改写属于同一统计族，bootstrap 以族为单位，区间不可解释为泛化保证。

## 4. R0 固定底座

材料包包含文档成员及哈希、Block/Chunk/来源映射、实际 float32 文档向量、查询向量、向量空间、配置、金标版本、代码与环境指纹。向量行序必须与 ID 映射一致，校验维度、行数、有限值和内容指纹。

快照只读导出。金标保留原始人工稿和已确认版本，模型候选仅作为建议。新增标注走新版本，不覆盖旧实验。导出中断且无完成清单的目录不算有效材料包。

每题保留 query_id、question、query_family、query_type、document_ids、snapshot_id、evidence_groups、scope_complete、review_status。必要时保留 should_abstain，但本轮仅用于无答案题分组。

补充 answer_units，逐项定义用于语义覆盖审核的必要事实，每项绑定原文证据。先独立冻结金标，再查看各模式结果。检索后的人工审核另存，字段含 result_run_id、query_id、mode、k、reviewer、review_status、candidate_relevance、answer_unit_coverage 和 reason，不能覆盖原始金标。候选相关性按 chunk_id 绑定，要点覆盖按 answer_unit_id 绑定，结果版本或 k 改变需重新核对。

建议试点中术语题 5～7 道、改写题 5～7 道、多证据题 5～6 道，具体分配由实际 PRD 决定；改写题与原题绑定 query_family。试点用于调试协议，不能同时宣称是独立留出验证。后续确认效果需要增加未参与调参的独立题或主题。

## 5. R1 三种检索模式

统一使用相同快照、问题、文档范围、k=5/10 及固定向量空间，关闭 rerank。候选召回预算先登记，建议每路 20、最终 k=5/10。该值是试点建议，材料冻结时记录最终值。

| 模式 | 组合 | 计时 |
|---|---|---|
| vector | 固定查询向量 → 原 NumpyIndex | 向量搜索 |
| keyword | 原 KeywordIndex → 词频排名 | 分词/构建和查询分别记录 |
| hybrid | 前两路排名 → 原 rrf | 两路搜索与融合分别记录 |

复用现有 KeywordIndex 的 jieba 分词及词频匹配，报告如实说明未使用 BM25。RRF 常数为 60，融合得分为各路 1/(60+rank) 之和。保持原组件的排序与过滤语义。

第一次索引构建与稳态查询分别测量，另外报告当前生产实现每题构建关键词索引的成本。导出查询向量的模型耗时和成本单列，不混入离线搜索内核耗时。

指标以 Recall@5/10、MRR@10 为主，P/F1、完整证据命中率和可计算的 nDCG 为补充。按术语、改写、多证据分层，报告空结果、失败数、每路候选与并集大小。候选扩大与排序改善分别解释，不预设 hybrid 一定优胜。

### 人工语义核对

借鉴 Amazon Bedrock 的上下文相关性和覆盖维度，在 R1 内补充两项人工评分，继续保留 R3 的可复算证据计数。

| 项目 | 审核单位 | 量表 | 每题汇总 |
|---|---|---|---|
| 人工上下文相关性 | 每个实际返回候选 | 0 不提供回答依据；0.5 有帮助但不足以直接支撑必要结论；1 直接支撑至少一个必要要点 | 实际已完整审核候选的平均分 |
| 人工答案要点覆盖率 | 当前 k 个候选组成的证据集合对每个必要要点的支持 | 0 未覆盖；0.5 部分覆盖且缺少明确子条件；1 完整覆盖该要点 | 所有已定义必要要点的等权平均分 |

两项评分维持 0～1，表示按本项目量表归一化的人工结果，不当作准确率或正确概率，也不冒用 AWS 服务输出的同名分数。必要要点尽量原子化；出现 0.5 时记录缺少的条件，试标中可据此进一步拆分要点，拆分后升版金标再重算。

例如撤回条件包含开关、操作状态及后续节点状态时，字符区间命中只能支持“找到了这个位置”的判定，人工还需逐项检查条件是否出现、是否被误读或属于冲突版本。语义覆盖不能直接替代区间 Recall，两个结果分别展示。

实际没有返回候选时，人工相关性为 null，空结果单列；有必要要点但集合为空时覆盖为 0。无答案题不计算要点覆盖，标为 null。存在未审核候选时，每题相关性暂不汇总；要点审核未完成时，覆盖暂不汇总，不能只平均已确认的高分项。跨模式比较使用相同有效问题集合，并报告排除数。

主报告分别列出证据 Recall、MRR、人工相关性和人工要点覆盖，不将不同分数再平均成一个总分。每项展示均值、有效题数、未知/失败数与问题类型分层。使用 0、(0,0.5)、0.5、(0.5,1)、1 五档计数直方图，区间边界互斥；另展示低分题和分歧题，避免平均值掩盖漏条件问题。

首批 15～20 题由人工完成审核，不新增付费评审调用。未来如引入 LLM 预筛，需固定模型、提示词、量表和上下文预算，隐藏配置名称，并保留人工复核与一致率；自动分数不得直接升级为人工金标。

参考 [AWS RAG 指标定义](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-evaluation-metrics.html)与[评审量表示例](https://docs.aws.amazon.com/bedrock/latest/userguide/model-evaluation-type-kb-prompt-nova-premier.html)，核对日期 2026-11-12。仅借鉴评测维度，本项目使用上述明确量表。

## 6. R2 后端、度量与工程成本

使用同一输入 float32 矩阵及查询，比较 NumPy/FAISS Flat 的 cosine、平方 L2、dot。开启与关闭归一化分别登记；单位向量下三种排序等价的检查单列。使用未归一化的合成矩阵演示模长影响，不能从已归一化业务缓存还原原始范数。

两条路径分别报告。第一条是原适配器路径，包含范围过滤、复制、验证和索引处理；当前 FAISS 每次搜索前还完整执行一次 NumPy 打分并重建范围内 Flat。第二条是预构建 native Flat 的稳定查询路径。NumPy 的完整 stable argsort 成本也包含在适配器查询中。native 路径只用于解释内核与装配成本，不能代替生产路径的结果。

先测当前快照真实规模及维度，再可选合成 1k/10k/100k。合成数据只用于性能，使用固定种子、非零有限向量和独立查询。每档确认可用内存，避免默认同时持有多份大矩阵。

记录 build、load、单查询 p50/p95、批量吞吐、磁盘及峰值内存。预热和正式重复次数预登记，试点可先采用每题至少 30 次及批量 5 次。固定并记录 BLAS/OpenMP 线程，单题 QPS 和批处理吞吐分开说明。索引 load 需注明实际持久化的是矩阵还是 native 索引，native 重建另计。

正确性按 ID 对齐分数后比较容差、集合重合和排名。随机无并列样本与人工构造并列样本分别检查；k 边界近似并列时允许多组等价结果。数值容差在看结果前按 dtype 与测试尺度确定。Flat 精确检索也可能获得 SIMD/批处理收益，收益大小由实验决定。
