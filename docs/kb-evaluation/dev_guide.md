# 知识库检索与问答评测开发指南

日期：2026-11-11。状态：目标契约与验收指南，终端工程首版已提供，实际状态见执行计划及 20261112 交付记录。旧实验工具已移除；历史运行数据已归档，恢复须按归档清单还原原路径。

## 1. 目标与范围

六份 Cordys CRM PRD 构成首批需求语料，先串行入库，在指定知识库及文档版本内检索并回答固定问题。评测解析、检索、证据使用、回答、拒答和效率。问答指标只支持问答结论；共享检索组件的结果也受语料、索引和查询分布约束，迁移到用例生成需重新验证。

现有用例生成 Pipeline 保留独立入口和单文档范围。新增流程复用解析、分块、embedding、度量、后端、关键词与重排实现，通过独立应用编排装配。图文分离、Vision、批量并发向量、FAISS、多种相似度和计时均保留。六份文件串行入库，多文档统一检索先于并发调度。首期 CLI，HTTP 鉴权、会话与流式响应属于后续交付。

现有设计依据为 [架构设计](../design/design_spec.md)，原生成开发路线为 [生成开发指南](../design/dev_guide.md)。旧 eval 工具已按用户要求移除。新入口统一放 eval/kb/；正式检索服务继续复用 src/tc_rag，评测指标按本指南重新验收。

## 2. 双线推进及阶段依赖

标注线从阶段 0 启动，与工程阶段 1、2 同期开展。这里的并行表示工作安排，自动代理分工仍依用户授权。

| 阶段 | 工作与交付 | 验收门槛 |
|---|---|---|
| 0 语料与试标 | 原件只读盘点、哈希、版本、正文图表与外链缺失记录；标注指南 v1、问题草案、审批流试标、一致性与仲裁记录 | 每题有证据和判定来源；未审核保持未知；原件及金标可定位 |
| 1 复用与回归基线 | 列出共享服务、单文档耦合、最小变更文件和领域契约；固定虚构样例捕获原生成入口结果；登记验证命令 | 原入口离线正常及失败路径可复现，历史数据读写边界明确 |
| 2 入库 | 先一份再六份；知识库、版本、状态、幂等；来源映射与快照式索引发布 | 重复导入无重复片段；失败保留旧快照；能查询六份明确版本 |
| 3a 仅检索 | 查询、文档范围、关键词融合、可选重排；候选、分数与阶段计时 | 不调用回答模型；范围隔离、并列排序与证据回查可验证 |
| 4a 检索实验 | 阶段 0 的冻结金标加 3a，跑基线、单因素、单文档与全库对照 | 指标可复算；未知与空分母口径明确；保留逐题排名和区间 |
| 3b 回答 | 3a 上叠加独立版本提示词、预算、答案及引用、证据不足处理 | 每条引用可解析到当前快照；失败和拒答有独立状态 |
| 4b 回答实验 | 冻结问答协议；独立题目运行；人工审核事实、引用、完整性和拒答 | 对照使用相同问题；记录模型重复运行和审核一致性 |
| 4c 汇总 | 冻结 B*，留出验证、失败归因、导师报告与复现附件 | 阈值、排除样本、限制和未执行检查完整披露 |

各阶段完成后记录实现状态、检查结果、未验证项和审核点，再沿用户指定阶段推进。阶段 4a 可在 3b 前交付。

## 3. 语料冻结和问题金标

首批文件为审批流与待办、产品、客户、商机、订单、模块设置。产品和模块设置图片较多，先核对图片承载的字段约束、外链表格及低文字量页面。以 DOCX 包内资产数作为盘点数据，不能当作独立业务图数量。

原始输入仅包含已登记 PRD。官方手册记录 URL、采集日期与版本，用于人工对齐。PRD 明确支持的内容进入主评分；手册独有事实记为输入缺口；冲突先核对版本，未决保留争议。手册示例、默认值与产品普遍规则分别标记。现有两份手册摘要只供定位，需要回查官方原文后才能确认标注。

建议试标 20 题，正式初始目标 80～120 题，实际数量根据规则盘点和人力调整后预登记。包含单段事实、多处联合、跨文档、数值或状态边界、图片证据、无答案及冲突题。每类报告样本数，不为凑数量编造业务事实。无法回答须注明缺失、冲突或问题范围不成立，不能把“当前未找到”直接标成无答案。

金标先于模型结果独立制作。两人试标同一批，分开记录答案要点、证据重叠与可回答性；对固定类别计算一致率或 κ，对区间给重叠统计。试标后制定一致性门槛及仲裁流程，达标再冻结。只有一位标注人时如实说明，安排导师复核抽样，不伪造独立双标。

每题字段至少包括 query_id、question、query_family、split、scope、answerability、evidence_groups、answer_units、review_status、annotators、adjudication、gold_version。scope 绑定 kb_snapshot 和文档版本。答案要点表示必须覆盖的事实，不强制措辞一致。evidence_groups 表示必要证据单元，每单元可列替代等价区间，防止把重复表述误当多项必要证据。

证据绑定文档版本哈希、解析文本版本、Block ID、半开区间 [start,end)、引文、章节及页码或表格位置。字符偏移以 Python Unicode 码点计数。浏览器 UTF-16 位置需转换。图片证据绑定资产哈希和位置，Vision 派生描述单独标识来源及审核状态。切换解析器后需验证或重新标注锚点。

dev 用于调参，test 在最终配置冻结后评估。按文档或关联主题组划分，近重复规则和同源题的改写放同侧。若六份文档关联过强，可固定全库索引并留出问题主题组，报告称“固定语料上的留出问题评测”，不能声称测试了未见文档泛化。test 答案不得用于提示词示例或调参；全库索引包含测试证据是固定知识库问答的正常设定。阶段 0 登记采用哪种划分和结论范围。

## 4. 数据和接口设计

domain 保存纯数据和指标逻辑；application 增加入库、范围检索、问答与评测服务；infrastructure 实现仓储、索引和模型 ports；bootstrap 分别装配原流程和新入口。先审查现有实现再确定模块路径，避免复制一套检索算法。

新增结构建议包括 KnowledgeBase、DocumentVersion、IngestionJob、KnowledgeSnapshot、SearchRun、AnswerRun。文档标识与内容版本分开；Chunk 标识包含文档版本及分块指纹，跨文档无冲突。快照记录精确文档版本清单、分块策略、模型及向量空间、索引格式版本和完整性指纹。

SQLite 保存入库、版本、发布指针和运行事实。新知识库采用独立 SQLite 及资产、索引、输出命名空间，路径可配置。人工标签是独立评测资料，JSONL 是冻结的交换格式，通过显式校验导入或关联，不能反向改写业务事实。原 workdir/rag/runtime/data.sqlite 及已有索引保持其现有引用。

建议命令形态为 kb ingest、kb list、kb search、kb ask、kb evaluate，均为拟议接口，实际名称在阶段 1 确认。search 和检索评分只装配必要的 embedder 与可选 reranker，不要求回答模型配置；ask 额外要求生成模型。原命令的配置必需项和语义保持兼容。

search 请求包含 kb_id、snapshot_id、query、文档过滤、候选数和最终 k。响应记录过滤范围、原召回与重排名次、原始度量及排序方向、融合分数、候选正文/文本指纹、来源、截断和降级、各阶段耗时。不同阶段的分数独立命名，不能当成统一相似度。

ask 在同一快照上消费 search 结果，输出状态、答案、声明与引用关联、实际发送给模型的证据范围、usage 和耗时。error、answered、abstained 分开，服务失败不能计为正确拒答。问答提示词单独放 prompts 下并版本化；语料和检索结果视为不可信数据，其中的指令不能覆盖系统任务。

## 5. 幂等、更新和快照发布

幂等键至少包含知识库、逻辑文档、内容哈希和解析/分块/向量配置指纹。同内容不同逻辑文档采用保留或去重策略须明文约定，不能静默改变来源。状态包含 pending、processing、ready、failed，失败记录阶段和可重试性。

文档重传、更新、删除及新增第七份文档，均构建新的候选快照。可以复用指纹匹配的解析和向量缓存，但新快照有完整且一致的成员表。相同模型名不足以认定同一向量空间，还需供应商/端点身份、维度、归一化及配置版本；空间变化重新构建。

发布前检查行数、ID 映射、维度、有限值、文件哈希及格式版本。先写临时目录，再完成文件发布，最后事务切换 SQLite 活跃指针。崩溃产生的孤立目录不对外可见，重试可识别并清理任务自有临时文件。查询开始时固定快照，整个召回、重排和回答保持相同版本。并发发布用条件更新或锁避免覆盖，旧快照由引用和保留策略回收。

坏格式、缺文件、错误维度、空库、过滤为空和不支持版本均有明确结果。新入口不把索引故障解释成无答案，也不回退到其他库。原生成流程仍在检索故障时停止。

## 6. 指标与统计协议

正式评分前登记主指标、k、相关度、重叠阈值、零分母、缺失与失败口径、随机种子、重复次数、通过门槛及其依据。门槛由试标和导师要求确认，本文不宣称任意数值达标。

| 指标 | 固定口径 |
|---|---|
| Recall@k | 前 k 候选覆盖的去重必要证据单元 / 全部必要证据单元，宏平均按问题计算。多处联合题另报全部证据找齐率 |
| Hit@k、MRR@k | 至少一项相关证据是否出现；第一个相关候选的倒数名次，截断外为 0 |
| Precision@k | 相关候选数 / k；少于 k 时空位按不相关，另外记录实际返回数。用于描述大块与重复候选局限 |
| nDCG@k | 分级相关度增益采用 2^grade-1。跨分块比较以首次覆盖证据单元获得增益、重复覆盖为 0，并保存理想增益及匹配算法版本 |
| 忠实性 | 有证据支持的原子事实声明 / 全部可判定事实声明，逐声明审核；无事实声明的拒答单列 |
| 引用精确率 | 支持所附声明的有效引用关联 / 全部引用关联。错误 ID 和不支持引用计错 |
| 引用召回率 | 已获得有效引用支持的应引用事实声明 / 全部应引用事实声明。另报金标答案要点的证据覆盖，避免与完整性混淆 |
| 正确性与完整性 | 人工按冻结量表评核心答案是否正确、加权金标要点覆盖率，错误附加事实进入错误与忠实性统计 |
| 拒答 P/R | 以应拒答为正类，P=正确拒答/所有拒答，R=正确拒答/应拒答；另报可回答题误拒率 |

未知相关性保持 null；完整相关集合未审核时 Recall 为 null。无答案题不进入需要正例分母的检索指标，单列拒答与误召回表现。空分母为 null 并报告计数，禁止自动补成满分。运行失败单列并报告成功率及端到端有效完成率，避免只保留成功样本。

任意区间相交可作宽松分析，正式主口径建议按金标区间覆盖比例设阈值，试标后冻结，并做严格/宽松敏感性对照。大块更易命中的偏差通过固定上下文预算、候选长度统计和证据覆盖同时呈现。

查询改写族或主题作为配对 bootstrap 单位；跨文档实验按文档/主题聚类，报告 95% 区间、有效问题数和簇数。六份文档下区间可能不稳定，不夸大显著性。对同一问题的配置差值做配对重采样，多因素探索在 dev，冻结 B* 后测试。回答重复运行次数提前登记，按题汇总再统计，避免把重复回答当独立问题。

计时分别记录向量化、索引搜索、融合、重排、证据组装、生成和端到端。检索内核性能采用固定矩阵、预热、固定线程、重复测量，单列网络与缓存状态。费用仅在 usage 和单价可信时估算，未知为 null。

## 7. 对照实验

基线使用固定语料快照、结构分块、一个向量空间、NumPy、既有默认度量、无融合无重排，具体参数记录后冻结。每次改变一个因素，首期比较分块策略/预算、度量与归一化、NumPy/FAISS、关键词融合、重排。归一化原始向量缺失时只做等价性检查，不能宣称完成原始六组合实验。

单文档对全库对照只使用答案证据完全存在于该目标文档的同一批问题，增加其他五份作为干扰，比较证据召回和排名。真正跨文档题另外分组，缺少必要证据的单文档条件属于证据不完整实验。两组都保存查询与范围，不混算质量收益。

Vision 对照限定含图片证据的问题；未处理图片导致的证据缺失归因到入库。向量模型对照需重新建空间。B* 组合后在 dev 复核交互作用，再冻结做留出验证。WeKnora 外部对照可后续纳入，须锁版本、同语料、问题、向量模型和范围，只在证据可映射时比较。

回答主评采用实际检索上下文，另可用人工选定证据生成回答以区分检索和生成误差，报告明确输入条件。DeepSeek 评审仅作预筛，使用独立评审提示词、版本和盲化配置标识，人工分层抽样覆盖拒答、冲突、错误及通过样本，记录抽样比例和一致率。无人工复核的自动评分明确标识。

## 8. 回归与失败路径

阶段 1 使用虚构文档、Fake 生成/向量/重排与真实离线索引，通过原 CLI 和连续生成入口建立基线。固定输入、时钟或规范化 run_id/路径/时间，保存分块区间、来源、向量哈希、检索 ID/名次和结构化最终用例。ZIP 导出比较工作簿与脑图语义，避免文件打包时间造成误报。真实模型结果只作人工参考，不能做逐字确定性回归。

修改共享组件时自动运行原入口回归和新增失败用例。哈希只在同一精度、序列化和环境下比较；浮点计算采用预登记容差及排序规则，跨后端并列允许按固定规则解释。不能通过更新快照掩盖行为变化，必要变更先记录原因和用户要求。

必测项目包括文档隔离与混合 ID、过滤为空、幂等重试、部分解析/向量失败、发布前后崩溃、并发发布冲突、更新删除后旧快照一致性、错误维度、索引版本不兼容、重排降级、提示词与引用预算、未知标签和零分母、拒答与服务错误区分。阶段检查使用 pytest、ruff、mypy 和 CLI 帮助，缺工具如实记录。真实模型与网络烟测独立授权。

## 9. 留档与导师报告

设计与可公开笔记放 docs；新增运行数据建议 workdir/kb/，私有语料冻结清单、金标与实验材料放 workdir/kb/evaluation/。实施前确认 Git 忽略规则。外部原件只读，不移动现有运行资产。每阶段维护学习笔记，包含目标、数据流、关键选择、遇到的问题、验证证据和待确认事项。

每次 run manifest 记录 run_id、代码提交及脏工作树补丁指纹、语料/金标/快照版本、配置与提示词指纹、模型和向量空间、依赖环境、随机种子、缓存、开始结束时间、usage、重试、失败与排除原因。不得包含凭据。逐题保存结果、实际上下文、候选与评分，未使用和待审核状态明确。

失败归因采用多标签并登记主要原因，顺序检查入库缺失、未召回、排名靠后、证据截断、未用证据、与证据矛盾、应拒未拒、误拒、引用错误，以及输入缺口和版本冲突。人工保留说明，不能仅凭自动规则宣称根因。

导师报告包含目标与适用范围、六份语料及划分、金标与一致性、指标门槛、环境和基线、检索与回答结果、单文档/全库对照、失败案例、性能与成本、结论与限制、复现附录。每个关键结果给样本数和区间；未运行项目标记未测，保留不可判定项。先交检索阶段报告，再补问答及最终报告。
