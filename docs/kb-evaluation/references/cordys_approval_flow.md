# Cordys CRM 审批流配置

官方来源：[审批流配置](https://docs.fit2cloud.com/cordys/user_manual/approval_flow/)  
整理日期：2026-11-10。用途：审批流 PRD 对齐参考。以下为人工标注前的候选核对项。

| 原文位置 | 核对主题 | 手册要点 |
|---|---|---|
| 第 1 节 · 基本信息 | 创建权限与必填项 | 新建需要流程设置的添加权限。业务类型、名称和执行时机必填，保存后业务类型不可修改。 |
| 第 1 节 · 流程设计 | 审批人 | 可按指定成员、角色或组织关系确定审批人。多级规则需确认审批到哪一级。 |
| 同上 | 多人审批 | 会签须全员同意，任一人驳回则结束。或签一人同意即可推进。依次审批按配置顺序推进，驳回后结束。 |
| 同上 | 异常处理 | 找不到审批人，或审批人与提交人相同，分别按所选异常策略处理。 |
| 同上 | 字段权限 | 节点可配置隐藏、查看或编辑。手册说明编辑权限只适用于单行及多行文本字段。 |
| 同上 | 条件分支 | 按字段、运算符和值配置。AND 要求全部条件满足，OR 要求至少一条满足。未命中进入其他分支。 |
| 第 1 节 · 更多设置 | 操作与意见 | 提交人撤销、审批人撤回、批量处理、加签和意见必填均需结合对应配置判断。 |
| 同上 | 自动审批与状态权限 | 重复审批人按全局策略处理。状态与操作矩阵是示例配置，标注时保留配置前提。 |
| 第 3 节 · 审批记录 | 报价示例 | 提审后进入审批中。第一个审批节点不支持退回。通过后可查看完整审批记录。 |

## 待与 PRD 对齐

- 分支示例的名称表达严格大于，实际示例配置使用 `>= 100000`。分别记录名称与运算符，确认等于阈值时的业务预期。
- 全局设置中的提交人撤销、审批人的撤回，以及节点退回是不同操作。对齐时分别记录角色、前置状态和可用条件。
- 示例里的金额和权限矩阵按示例标记。对应 PRD 的实际配置与版本待确认。
