## 3. 生成上下文记录已接入

新增`application/services/generation_context.py`，在Pipeline._model预算检查通过后记录规划/用例阶段的应用层输入。仅保存所需的规则/功能/点ID、核心和补充证据、指纹、状态及文档指纹，不复制未知请求字段、完整配置或密钥。

SQLite继续是运行事实来源，无新表或迁移：每次模型请求形成独立StageSnapshot，索引为`RUN_ID:generation_contexts`，记录stage为`generation_context`。两轮检索记录中的`generation.evidence_fingerprint`可与其对照；原有adopted_ids/omitted_ids保持。

| 状态 | 表示什么 | 不表示什么 |
|---|---|---|
| prepared | 应用层已准备记录，尚无已完成模型结果 | 不表示远端已收到请求 |
| model_started | 已开始调用模型适配器 | 不证明远端服务接受或完成 |
| model_completed | 适配器返回结果 | 不代表测试语义正确或交付成功 |
| model_error | 适配器调用异常，记录异常类型 | 不视作正确拒答或成功 |
| cache_hit | 使用已有结果，本次未调用模型 | 不新增模型使用量 |
| cancelled | 当前模型调用被取消 | 不算已完成 |

记录不添加到模型request，不改变提示词、生成策略、检索范围或调用次数。记录持久化失败不静默吞掉，会阻止继续正常生成；这保证审计不能失败后仍宣称完整记录。这里保存的是应用层证据，不是远端HTTP原始请求抓包；也未实现自动语义评分或唯一原文区间的全量映射。

历史运行不会自动补写。当前无需为验证日志再付费跑生成；下次由用户启动的新运行会自动记录。

只读导出已有新版运行：

```powershell
.\.venv\Scripts\python.exe eval/kb/export_generation_contexts.py --database workdir/rag/runtime/data.sqlite --run-id RUN_ID --output workdir/kb/evaluation/feature_pilot/runs/RUN_ID_contexts
```

将RUN_ID替换为真实运行标识，数据库路径按实际部署指定。输出包含需求正文，保留在私有评测目录；旧运行没有记录时明确报错，不发起模型补采。
